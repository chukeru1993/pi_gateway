# Pi RPC 模式完整协议规范

## 一、概述

RPC 模式允许通过 JSON 协议在 stdin/stdout 上无头运行 coding agent，用于将 agent 嵌入其他应用、IDE 或自定义 UI。

启动方式：
```bash
pi --mode rpc [--provider <name>] [--model <pattern>] [--no-session] [--session-dir <path>]
```

在 [main.ts:678](file:///Users/chukeru/GitHubProjects/pi/packages/coding-agent/src/main.ts#L678) 中，当 `appMode === "rpc"` 时调用 `runRpcMode(runtime)`。

---

## 二、帧协议 (JSONL)

- 使用严格的 JSONL 语义，LF (`\n`) 是唯一的记录分隔符
- 输入端接受可选的 `\r\n`（自动剥离尾部 `\r`）
- **禁止**使用 Node `readline`，因为它会在 U+2028/U+2029 处拆分（这些在 JSON 字符串内是合法的）
- 每条记录是一个 JSON 对象，后跟 `\n`

实现见 [jsonl.ts](file:///Users/chukeru/GitHubProjects/pi/packages/coding-agent/src/modes/rpc/jsonl.ts)：
- `serializeJsonLine(value)`: 返回 `JSON.stringify(value) + "\n"`
- `attachJsonlLineReader(stream, onLine)`: 严格按 `\n` 分割的行读取器

## 三、命令 (stdin -> agent)

所有命令都是 JSON 对象，必须包含 `type` 字段，可选 `id` 字段用于请求/响应关联。

### 3.1 提示类 (Prompting)

#### prompt
```json
{
  "id": "req-1",           // 可选，用于关联响应
  "type": "prompt",
  "message": "Hello, world!",
  "images": [              // 可选
    {"type": "image", "data": "base64...", "mimeType": "image/png"}
  ],
  "streamingBehavior": "steer"  // 可选: "steer" | "followUp"
}
```

- 若 agent 正在流式输出且未指定 `streamingBehavior`，命令返回错误
- `"steer"`: 在当前 assistant turn 完成工具调用后注入，下次 LLM 调用前
- `"followUp"`: 等 agent 完全停止后注入
- 扩展命令（如 `/mycommand`）即使在流式期间也立即执行
- Skill 命令和 prompt template 会在发送/排队前展开

**响应是异步的**：`success: true` 仅表示 prompt 被接受/排队/立即处理。后续事件通过事件流异步推送。

#### steer
```json
{"id": "req-2", "type": "steer", "message": "Stop and do this instead", "images": [...]}
```
- 排队一条转向消息，不允许扩展命令（用 `prompt` 代替）
- Skill 命令和 prompt template 会被展开

#### follow_up
```json
{"id": "req-3", "type": "follow_up", "message": "After you're done, also do this", "images": [...]}
```
- 排队一条后续消息，不允许扩展命令

#### abort
```json
{"id": "req-4", "type": "abort"}
```

#### new_session
```json
{"id": "req-5", "type": "new_session", "parentSession": "/path/to/parent.jsonl"}  // parentSession 可选
```
- 可被扩展的 `session_before_switch` 事件处理器取消

## 五、事件流 (agent -> stdout)

事件是 `AgentEvent` 对象，在 agent 运行期间异步流式输出。事件**不包含** `id` 字段。

### 5.1 事件类型总览

| 事件 | 描述 |
|------|------|
| `agent_start` | Agent 开始处理 |
| `agent_end` | Agent 完成（包含所有生成的消息） |
| `turn_start` | 新 turn 开始 |
| `turn_end` | Turn 完成 |
| `message_start` | 消息开始 |
| `message_update` | 流式更新（文本/思考/工具调用增量） |
| `message_end` | 消息完成 |
| `tool_execution_start` | 工具开始执行 |
| `tool_execution_update` | 工具执行进度 |
| `tool_execution_end` | 工具执行完成 |
| `queue_update` | 转向/后续队列变化 |
| `compaction_start` | 压缩开始 |
| `compaction_end` | 压缩完成 |
| `auto_retry_start` | 自动重试开始 |
| `auto_retry_end` | 自动重试结束 |
| `extension_error` | 扩展抛出错误 |

### 5.2 各事件详细格式

#### agent_start
```json

```

#### turn_start / turn_end

#### message_start / message_end

#### message_update（流式核心）
```json
{
  "type": "message_update",
  "message": {...},
```

`assistantMessageEvent` 的子类型：

| 类型 | 描述 |

## 六、扩展 UI 子协议

扩展通过 `ctx.ui.select()`、`ctx.ui.confirm()` 等方法请求用户交互。在 RPC 模式下，这些被翻译为 stdout 上的请求和 stdin 上的响应。

### 6.1 两类方法

**对话方法**（`select`、`confirm`、`input`、`editor`）：发出 `extension_ui_request`，阻塞等待客户端返回 `extension_ui_response`。

**即发即弃方法**（`notify`、`setStatus`、`setWidget`、`setTitle`、`set_editor_text`）：发出 `extension_ui_request`，不期望响应。

### 6.2 扩展 UI 请求 (stdout)

## 八、流式事件工作流程

典型的 prompt -> 响应完整事件序列：

```
1. 客户端发送: {"type": "prompt", "message": "Hello"}
2. Agent 输出: {"type": "response", "command": "prompt", "success": true}  // prompt 被接受
3. Agent 输出: {"type": "agent_start"}
4. Agent 输出: {"type": "turn_start"}
5. Agent 输出: {"type": "message_start", "message": {...}}
6. Agent 输出: {"type": "message_update", "message": {...}, "assistantMessageEvent": {"type": "text_start", ...}}
7. Agent 输出: {"type": "message_update", "message": {...}, "assistantMessageEvent": {"type": "text_delta", "delta": "Hello", ...}}
8. ...更多 text_delta ...
9. Agent 输出: {"type": "message_update", "message": {...}, "assistantMessageEvent": {"type": "text_end", ...}}
10. Agent 输出: {"type": "message_update", "message": {...}, "assistantMessageEvent": {"type": "done", ...}}
11. Agent 输出: {"type": "message_end", "message": {...}}
12. Agent 输出: {"type": "turn_end", "message": {...}, "toolResults": []}
13. Agent 输出: {"type": "agent_end", "messages": [...]}
```

如果涉及工具调用，在 `message_end` 后会插入 `tool_execution_*` 事件，然后可能开始新的 turn。

## 九、Steer / FollowUp 工作机制

### 9.1 Steer（转向）

- 通过 `steer` 命令或 `prompt` 命令带 `streamingBehavior: "steer"` 发送
- 消息被放入转向队列
- 在当前 assistant turn 完成工具调用后、下次 LLM 调用前注入
- 投递模式由 `set_steering_mode` 控制：
  - `"all"`: 一次性投递所有
  - `"one-at-a-time"`: 每个 turn 完成后投递一条（默认）
- 队列变化时触发 `queue_update` 事件

### 9.2 FollowUp（后续）

- 通过 `follow_up` 命令或 `prompt` 命令带 `streamingBehavior: "followUp"` 发送
- 消息被放入后续队列
- 仅当 agent 没有更多工具调用和转向消息时投递
- 投递模式由 `set_follow_up_mode` 控制：
  - `"all"`: agent 停止时一次性投递
  - `"one-at-a-time"`: 每次 agent 完成投递一条（默认）

### 11.2 JSON 解析错误

无法解析的行返回：

### 11.3 Prompt 特殊处理

`prompt` 命令使用 preflight 机制（[rpc-mode.ts:389-411](file:///Users/chukeru/GitHubProjects/pi/packages/coding-agent/src/modes/rpc/rpc-mode.ts#L389-411)）：
- `success: true` 仅在 preflight 成功后发出
- 若 preflight 失败，发出 `success: false` 错误响应
- 接受后的失败通过正常事件/消息流报告，不会为同一 id 发第二个 response

### 11.4 进程级错误

- stdin EOF：触发 `shutdown()`
- SIGTERM/SIGHUP：杀死分离子进程后关闭
- `RpcClient` 端：进程异常退出时 reject 所有 pending 请求

5. 分离 stdin 读取器
6. 暂停 stdin
7. 刷新 stdout（SIGTERM 除外）
8. `process.exit()`

## 1. 进程管理：会话池

每个用户/业务会话对应一个 pi RPC 子进程。

```typescript
class PiProcessPool {
  private processes = new Map<string, PiProcess>();

  async create(sessionId: string, options: CreateOptions): Promise<PiProcess> {
    const args = ["--mode", "rpc"];
    if (options.provider) args.push("--provider", options.provider);
    if (options.model) args.push("--model", options.model);
    if (options.noSession) args.push("--no-session");
    if (options.sessionDir) args.push("--session-dir", options.sessionDir);
    if (options.cwd) args.push("--cwd", options.cwd);

    const proc = spawn("pi", args, { cwd: options.cwd });
    const pi = new PiProcess(sessionId, proc);
    this.processes.set(sessionId, pi);

    // 空闲超时自动回收
    pi.startIdleTimer(30 * 60_000); // 30 分钟
    return pi;
  }

  get(sessionId: string): PiProcess | undefined {
    return this.processes.get(sessionId);
  }

  async destroy(sessionId: string): Promise<void> {
    const pi = this.processes.get(sessionId);
    if (pi) {
      this.processes.delete(sessionId);
      await pi.shutdown();
    }
  }
}
```

`PiProcess` 封装子进程的 JSONL 读写：

```typescript
class PiProcess {
  private proc: ChildProcess;
  private requestId = 0;
  private pendingResponses = new Map<string, {
    resolve: (msg: any) => void;
    reject: (err: Error) => void;
    timer: NodeJS.Timeout;
  }>();
  private eventListeners = new Set<(event: any) => void>();
  private uiRequestHandlers = new Map<string, {
    resolve: (value: any) => void;
  }>();

  constructor(public sessionId: string, proc: ChildProcess) {
    this.proc = proc;
    this.attachReader();
  }

  private attachReader() {
    let buffer = "";
    this.proc.stdout!.on("data", (chunk: Buffer) => {
      buffer += chunk.toString("utf8");
      while (true) {
        const idx = buffer.indexOf("\n");
        if (idx === -1) break;
        const line = buffer.slice(0, idx);
        buffer = buffer.slice(idx + 1);
        if (line.endsWith("\r")) line = line.slice(0, -1);
        this.handleLine(JSON.parse(line));
      }
    });
  }

  private handleLine(msg: any) {
    if (msg.type === "response" && msg.id) {
      const pending = this.pendingResponses.get(msg.id);
      if (pending) {
        clearTimeout(pending.timer);
        this.pendingResponses.delete(msg.id);
        if (msg.success) pending.resolve(msg);
        else pending.reject(new Error(msg.error));
      }
      return;
    }

    if (msg.type === "extension_ui_request") {
      // UI 请求特殊处理：通过事件流转发给前端
      for (const listener of this.eventListeners) {
        listener(msg);
      }
      return;
    }

    // 其他都是事件
    for (const listener of this.eventListeners) {
      listener(msg);
    }
  }

  async sendCommand(cmd: any, timeout = 30_000): Promise<any> {
    const id = `req_${++this.requestId}`;
    return new Promise((resolve, reject) => {
      const timer = setTimeout(() => {
        this.pendingResponses.delete(id);
        reject(new Error(`Command timeout: ${cmd.type}`));
      }, timeout);

      this.pendingResponses.set(id, { resolve, reject, timer });
      this.proc.stdin!.write(JSON.stringify({ ...cmd, id }) + "\n");
    });
  }

  sendUiResponse(id: string, response: any) {
    this.proc.stdin!.write(
      JSON.stringify({ type: "extension_ui_response", id, ...response }) + "\n"
    );
  }

  onEvent(listener: (event: any) => void): () => void {
    this.eventListeners.add(listener);
    return () => this.eventListeners.delete(listener);
  }

  async shutdown() {
    this.proc.kill("SIGTERM");
    setTimeout(() => this.proc.kill("SIGKILL"), 1000);
  }
}
```

**关键设计**：将 `message_update` 中的 `assistantMessageEvent` 拆分为独立 SSE 事件类型，前端更容易处理。

实现：

```typescript
app.post("/sessions/:id/chat", async (req, reply) => {
  const { id } = req.params;
  const { message, images, streamingBehavior } = req.body;
  const pi = pool.get(id);
  if (!pi) return reply.code(404).send({ error: "Session not found" });

  reply.raw.writeHead(200, {
    "Content-Type": "text/event-stream",
    "Cache-Control": "no-cache",
    Connection: "keep-alive",
    "X-Accel-Buffering": "no",
  });

  const sse = createSSEWriter(reply.raw);

  // 订阅 pi 事件
  const unsubscribe = pi.onEvent((event) => {
    if (event.type === "extension_ui_request") {
      // UI 请求：转发给前端等待响应
      sse.write("user_question", {
        id: event.id,
        method: event.method,
        title: event.title,
        message: event.message,
        options: event.options,
        placeholder: event.placeholder,
        prefill: event.prefill,
        timeout: event.timeout,
      });
      return;
    }

    // RPC 事件 → SSE 事件
    switch (event.type) {
      case "message_update": {
        const ame = event.assistantMessageEvent;
        if (ame.type === "text_delta") {
          sse.write("text_delta", {
            contentIndex: ame.contentIndex,
            delta: ame.delta,
          });
        } else if (ame.type === "thinking_delta") {
          sse.write("thinking_delta", {
            contentIndex: ame.contentIndex,
            delta: ame.delta,
          });
        } else if (ame.type === "toolcall_end") {
          sse.write("toolcall_end", {
            contentIndex: ame.contentIndex,
            toolCall: ame.toolCall,
          });
        }
        break;
      }
      case "message_start":
        sse.write("message_start", { message: event.message });
        break;
      case "message_end":
        sse.write("message_end", { message: event.message });
        break;
      case "tool_execution_start":
        sse.write("tool_execution_start", {
          toolCallId: event.toolCallId,
          toolName: event.toolName,
          args: event.args,
        });
        break;
      case "tool_execution_update":
        sse.write("tool_execution_update", {
          toolCallId: event.toolCallId,
          partialResult: event.partialResult,
        });
        break;
      case "tool_execution_end":
        sse.write("tool_execution_end", {
          toolCallId: event.toolCallId,
          result: event.result,
          isError: event.isError,
        });
        break;
      case "compaction_start":
        sse.write("compaction_start", { reason: event.reason });
        break;
      case "compaction_end":
        sse.write("compaction_end", event);
        break;
      case "agent_end":
        sse.write("agent_end", { messages: event.messages });
        unsubscribe();
        sse.end();
        break;
      case "extension_error":
        sse.write("error", {
          message: event.error,
          extensionPath: event.extensionPath,
        });
        break;
    }
  });

  // 连接断开时清理
  req.raw.on("close", () => {
    unsubscribe();
  });

  // 发送 prompt 命令
  try {
    await pi.sendCommand({
      type: "prompt",
      message,
      images,
      streamingBehavior,
    });
  } catch (err: any) {
    sse.write("error", { message: err.message });
    sse.end();
  }
});
```

## 7. 前端对接示例

```javascript
const sessionId = "sess_1";

// 1. 创建会话
await fetch("/sessions", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ provider: "anthropic", model: "claude-sonnet-4-5" }),
});

// 2. 发送消息，接收 SSE 流
const eventSource = new EventSource(`/sessions/${sessionId}/chat`, {
  method: "POST",
  body: JSON.stringify({ message: "解释这个代码库" }),
});

// 注意：标准 EventSource 不支持 POST，需要用 fetch + ReadableStream
const response = await fetch(`/sessions/${sessionId}/chat`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ message: "解释这个代码库" }),
});

const reader = response.body.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;

  const text = decoder.decode(value);
  for (const chunk of parseSSE(text)) {
    switch (chunk.event) {
      case "text_delta":
        appendToUI(chunk.data.delta);
        break;
      case "tool_execution_start":
        showToolExecution(chunk.data);
        break;
      case "user_question":
        // 弹出确认对话框
        const answer = await showConfirmDialog(chunk.data);
        // 回答
        await fetch(`/sessions/${sessionId}/ui-response`, {
          method: "POST",
          headers: { "Content-Type": "application/json" },
          body: JSON.stringify({
            id: chunk.data.id,
            confirmed: answer,
          }),
        });
        break;
      case "agent_end":
        console.log("Agent completed");
        break;
    }
  }
}
```

## 8. 方案总结

| 维度 | 方案 |
|------|------|
| **底层通信** | pi `--mode rpc` 子进程，JSONL over stdin/stdout |
| **对外协议** | RESTful API + SSE 流 |
| **会话模型** | 每用户一个 pi 子进程，空闲超时回收 |
| **流式输出** | SSE，将 `message_update` 拆分为 `text_delta`/`thinking_delta`/`toolcall_end` |
| **用户交互** | `user_question` SSE 事件 + `POST /ui-response` 端点，异步往返 |
| **中途追加** | `POST /steer` 和 `POST /follow-up` |
| **安全** | JWT 认证 + cwd 白名单 + 并发限制 |
| **部署** | Docker，每个 Gateway 实例管理最多 50 个 pi 子进程 |

核心优势：**零侵入**——不需要修改 pi 任何源码，完全基于官方 RPC 协议封装。
